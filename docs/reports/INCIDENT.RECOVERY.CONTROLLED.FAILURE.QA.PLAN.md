# Plan de certificación controlada de fallos — Centro de recuperación

- **Estado:** PREPARADO, NO EJECUTADO
- **Fase:** LANZO-POS Fase 3
- **Prerrequisito:** autorización y plan de certificación separados
- **Uso de producción:** prohibido

## Objetivo y límites

Este plan certificará el comportamiento del Centro de Recuperación ante fallos reproducibles en un entorno desechable. Durante Fase 3 no se inyectaron errores reales ni se alteraron conexiones, bases, cajas, ventas, pedidos, pagos o sesiones de negocios.

Todos los escenarios usarán negocio, licencia, dispositivo, actores y datos ficticios. La prueba debe detenerse si alguna solicitud apunta a un proyecto, tenant, dominio o dispositivo productivo. No se publicará un disparador de errores arbitrarios ni un modo de fallo habilitable desde producción.

## Prerrequisitos comunes

- Entorno aislado y aprobado: Supabase local, proyecto temporal autorizado o una rama de base de datos aislada. El staging histórico disponible está inactivo; no se considera apto sin restaurarlo y validar su aislamiento.
- Build de prueba separado, con credenciales y dominios de prueba; nunca reutilizar tokens o licencias de producción.
- Licencia, tenant, dispositivo y actores ficticios, identificados con prefijo `QA-INCIDENT-`.
- Respaldo verificable del entorno, snapshot o mecanismo de destrucción/restauración probado antes del primer caso.
- Instrumentación de evidencia que guarde solo códigos, estados, folios ficticios y capturas redactadas. No guardar tokens, cookies, datos personales ni payloads comerciales.
- Guardas para deshabilitar cobros, proveedores de pago reales, sincronización productiva, correo saliente y tareas programadas no necesarias.
- Un responsable de prueba puede detener la ejecución de inmediato. La prueba termina si el origen no se puede verificar, falla el aislamiento o aparecen datos no ficticios.

Si no se cumplen estos prerrequisitos, cada escenario permanece **BLOQUEADO**. No se sustituye el entorno aislado con una cuenta o un negocio real.

## Evidencia de certificación

Por escenario registrar versión/commit del build QA, ID del escenario, hora UTC, entorno aislado, resultado esperado/observado, número de llamadas y folio ficticio cuando exista. Adjuntar capturas redactadas y resultados automáticos; nunca adjuntar dumps de IndexedDB, payloads comerciales, tokens o datos personales.

Cada escenario recibe `PASS`, `FAIL` o `BLOCKED` únicamente después de ejecutarse en su entorno aislado. La aprobación de tests unitarios, mocks o contratos estáticos no certifica los casos reales de este plan.

**Estado en Fase 3:** todos los escenarios anteriores están `DEFERRED / NOT RUN`. No se ejecutó una inyección controlada de fallos.
